# V2.2.5 — Daily Record Exception Handling Fix

## Root cause
Layer and Broiler daily record saves could enter an exception handler that called
`safeUserExceptionMessage()` even though the helper was not available in the
common bootstrap. PHP therefore raised a fatal `Call to undefined function`
error and returned HTTP 500.

## Fix
- Added `safeUserExceptionMessage()` to `config.php`, which is loaded by the
  application bootstrap.
- Known actionable validation messages remain user-visible.
- SQLSTATE, SQL text, filesystem paths and driver details are suppressed.
- Unknown exceptions are logged server-side and shown with a safe fallback.
- Added a regression contract test for helper availability and safe redaction.

## Important
This fixes the secondary fatal error. After deployment, Layer and Broiler daily
record saves must be retested. If an underlying feed/inventory exception remains,
it will now be returned as a normal application notification instead of being
masked by the missing-helper fatal error.
